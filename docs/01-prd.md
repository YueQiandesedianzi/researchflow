# 01 — 产品需求文档（PRD）

版本：v0.1-draft｜日期：2026-11-13｜状态：待评审

## 1. 背景与问题

科研 Agent（DSH / Codex）可以不断生成代码，但很难保证每一次实验与前一次实验
在**数据、方法、评价标准和结果**上具有可靠的继承关系。典型症状：

- 每个会话重新发明数据划分 / 评价方式，结果之间不可比；
- 实验状态散落在对话历史里，换会话即丢失；
- 为每个候选模型复制一份脚本，改一处漏三处；
- "这个新方法真的比基线好吗"缺乏统一、留痕的判定；
- 投稿前无法回答"这张图是从哪份数据、哪段代码、哪次运行来的"。

## 2. 产品定位

ResearchFlow 把科研建模过程转化为**可组合、可执行、可验证、可追溯的实验工作树**：

> 将科研论文中的方法拆解为可复用的实验模块（Blocks），利用 AI 自动组合、执行和
> 比较实验，并通过人工审核与程序验证，形成可追溯、可复现的科研工作树。

它是**框架 + 插件**：Core 平台无关，DSH / Codex 各有薄适配器，领域能力靠积木包扩展。

## 3. 目标用户与场景

首要用户：使用 AI Agent 做计算/数据驱动科研的研究者（材料、化学、时序预测等）。

| 场景 | 说明 |
| --- | --- |
| S1 立项 | Agent 一键初始化标准科研项目，生成目录、配置与工作规范 |
| S2 复现论文方法 | 把论文方法拆成积木（或复用已有积木），在实验树上搭建流程 |
| S3 多方案对比 | 同一划分下挂多个模型分支，统一指标、自动对照 |
| S4 研究决策 | 决策节点记录"是否优于基线/是否继续探索"，可自动判定或人工确认 |
| S5 投稿准备 | 选中实验节点，一键导出含证据链的复现包与论文组图素材 |

## 4. 核心价值

1. **Scientific Blocks**：科研方法积木化——契约明确、可复用、可验证。
2. **Experiment Tree**：持续探索、比较、回退，研究决策留痕。
3. **Research Provenance**：数据 → 配置 → 代码 → 运行 → 图表的完整证据链。

## 5. 范围

### 5.1 MVP（v0.1）范围内

六项能力 + 两类数据：

| # | 能力 | 摘要 |
| --- | --- | --- |
| 1 | Project Init | 生成标准目录、配置和 AGENTS.md |
| 2 | Block Registry | 注册、检查和复用标准实验模块 |
| 3 | Visual Plan | 自动生成可编辑的实验流程图（Mermaid/JSON） |
| 4 | Run & Validate | 运行指定节点，自动验收，不合格阻断 |
| 5 | Compare Runs | 统一比较模型和实验分支 |
| 6 | Export Research | 导出选定结果及可复现代码 |

数据类型：**① 表格回归；② 时间序列回归**（共享同一套基础积木，验证通用性）。

### 5.2 明确不做（MVP）

- PDF 论文自动拆解为积木；
- Agent 自动生成新积木（只复用 + 人工编写）；
- 大规模并行试错编排（交由 dsh_workflow 等，留集成点）；
- 复杂可视化界面（仅 CLI 文本 / Mermaid 输出）；
- 图像、模拟、多目标优化、主动学习等领域积木包（架构预留，后续版本）；
- 修改或删除用户既有项目的任何内容。

## 6. 功能需求

### FR-1 Project Init

- `rf init` 在目标目录生成标准结构（见 [04](04-experiment-tree.md) 第 2 节）：
  `researchflow.yaml`、`plan.yaml` 骨架、`blocks/`、`data/`、`.researchflow/`、
  `.gitignore`、`AGENTS.md`。
- `--template tabular|timeseries` 生成含示例工作树的 plan。
- 幂等：已存在的文件不覆盖（`--force` 除外）；在非空目录运行需确认。

### FR-2 Block Registry

- 三级发现：项目 `blocks/` > 已安装积木包（entry points `researchflow.blocks`）> 内置。
- `rf blocks list/check`：列出、按 [Schema](03-block-schema.md) 校验积木。
- 同名积木项目级覆盖已安装级；版本冲突给明确报错。
- **契约强制**：输入端口类型不符、必需参数缺失、版本范围不满足 → 拒绝执行并说明原因。

### FR-3 Plan Engine（实验工作树）

- `plan.yaml` 描述两类节点：**执行节点**（绑定积木 + 参数 + 输入）与
  **决策节点**（自动判据 / 人工确认）。
- `rf plan validate` 静态检查（DAG 无环、引用存在、契约匹配）。
- `rf plan show --format mermaid` 输出流程图，节点附带运行状态着色。
- 计划是**可编辑意图**：人 / Agent 直接改 YAML；运行状态只存在 Registry，不写回计划。

### FR-4 Run & Validate

- `rf run <node-id>`：解析依赖拓扑，按需先跑上游；每节点执行后进入 Validation Gate。
- 验证器 = 积木声明的内置验证器（如 `no_group_overlap`）+ 积木自带 `validate` 钩子。
- 验证失败：Run 标记 `failed_validation`，下游节点阻断，事件落盘。
- 确定性积木命中内容寻址缓存时复用结果（`--no-cache` 关闭）。
- `requires_approval: true` 的积木 / 人工决策节点：CLI 交互确认；
  适配器层映射为平台审批机制。

### FR-5 Experiment Registry

- 每次运行生成独立 `RUN-######`，记录：节点、积木版本+哈希、参数哈希、输入产物哈希、
  Git commit、环境摘要、状态、指标、验证结果、产物清单（见 [04](04-experiment-tree.md) 第 4 节）。
- SQLite 索引 + 文件系统产物；状态只增不改，支持多会话并发读写。
- `rf status` / `rf runs` 查询工作树全景与单次运行详情。

### FR-6 Compare Runs

- `rf compare <run|node>...`：统一指标表（Markdown/CSV/JSON），指定基线后输出相对差异；
  回归任务内置 parity 对照图生成。
- 比较只基于 Registry 中的持久记录，不依赖任何会话上下文。

### FR-7 Export Research

- `rf export --nodes a,b,c --out <dir>`：收集所选节点的产物、解析后的配置快照、
  使用到的积木源码快照、环境锁定文件、`PROVENANCE.json`（完整追溯链）、
  复现说明 README 与 `reproduce.sh`。
- `--verify`：在导出目录内重跑关键节点并比对指标容差，通过才封包。

### FR-8 领域积木（MVP 两个包）

- `rf-blocks-tabular`：表格回归（载入、检查、随机/分组/折间划分、特征选择、
  sklearn 系训练、回归指标、parity/残差图）。
- `rf-blocks-timeseries`：时间序列回归（时序留出、滚动原点划分、滞后特征、
  共享训练/指标积木、预测序列图）。
- 清单与契约见 [03](03-block-schema.md) 第 6 节；两包共享 ≥60% 积木以证明通用性。

## 7. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 平台无关 | Core 仅依赖 Python 生态；`import researchflow` 不触碰 DSH / Codex 任何接口 |
| 可复现 | 确定性积木给定相同输入哈希必得相同输出哈希；Run 记录环境摘要与依赖锁定 |
| 可追溯 | 任一导出产物可沿 PROVENANCE 链回溯到原始数据文件与代码版本 |
| 可扩展 | 新领域 = 新积木包，不改 Core；积木 Schema 有 `schema_version` |
| 多会话协作 | 状态全在文件 + SQLite；两个 Agent 会话可同时对同一项目工作（节点级锁） |
| 安全 | Runner 只执行 Registry 校验过的积木；产物写入限制在项目 `.researchflow/` 内；外部命令型积木 MVP 不支持 |
| 性能 | 单节点调度开销 < 1s（不计积木本体耗时）；Registry 万级 Run 查询无感 |

## 8. 验收标准（与任务书一致）

1. 不依赖某个特定数据集；
2. 能组合至少三个不同类型的实验积木；
3. 能生成和保存实验工作树；
4. 能记录每个节点的输入、输出和运行状态；
5. 能阻止不符合输入契约的任务执行；
6. 能根据运行记录重新生成关键实验结果；
7. 能在两个独立任务（表格回归 demo + 时间序列回归 demo）中运行同一套基础积木；
8. 核心模块不依赖 DSH 或 Codex 的私有接口。

## 9. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 积木契约设计过窄，换领域即推翻 | 高 | MVP 就用两个差异较大的数据类型压测契约；端口类型保持小而正交 |
| Agent 绕过 CLI 直接改 Registry | 中 | AGENTS.md 明确禁令 + Registry 只增不改设计 + `rf doctor` 一致性检查 |
| 平台机制升级（DSH/Codex） | 中 | 适配器薄且隔离；Core 零平台依赖；版本兼容矩阵（见 [06](06-mvp-plan.md)） |
| 与 dsh_workflow 功能观感重叠 | 低 | 文档明确定位分工；提供集成示例而非竞争 |
